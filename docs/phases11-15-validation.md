## Scope implemented

- Phase 11: booking-scoped check-in, participant-authenticated start and end, completion only after both participants acknowledge the end, not-before-scheduled-time gate, transactional system messages.
- Phase 12: one 1–5-star review per side of each completed booking, reviews access limited to booking participants, average companion rating and review count based on stored reviews.
- Phase 13: user blocks, reports, private trusted-contact CRUD, booking-scoped recorded SOS alerts that explicitly do NOT dispatch to emergency services. Booking creation and sending chat messages fail if blocked.
- Phase 14: admin role protected summary, user/booking/report lists and audit-logged non-admin status moderation. No admin frontend.
- Phase 15: vendor product drafts, admin publication, public in-stock catalog and customer cart, pricing preview that leaves delivery fee unspecified. Gift payment/order/delivery checkout intentionally returns 503 until policies and providers are approved.

- Native PostgreSQL tests of locking/concurrency remain unverified because Docker Desktop's Linux engine responded HTTP 500. In-memory SQLite tests cannot establish production concurrency correctness.
- Redis was not running locally. Messages are committed and retrievable when publish fails, but end-to-end realtime WebSocket fan-out is not validated.
- Do not claim real payments, id/selfie verification, payout transfer or emergency dispatch are operational. Real provider adapters are not configured.
- Payment cancellation/refund/dispute/fee settlement policy still requires explicit product decisions. Payout release and dispute handling require further end-to-end integration.
- Phase 11 lacks GPS/proximity verification and real-device presence validation.
- Phase 13 needs operational Trust & Safety review workflows, trusted-contact sharing/notification, live emergency escalation, moderation/dispute processes, and stronger block visibility for personalized public discovery.
- Phase 14 needs full dashboard UI, moderation tooling, refund/payout reconciliations, and reporting permissions/hardening.
- Phase 15 lacks gift image upload, vendor self-service editing, order and delivery entities/fulfilment and secure gift checkout. Never interpret the subtotal preview as a payable invoice. No delivery fee, fee policy or vendor payouts are invented.
- Phase 7 distance requires real location data and approved privacy policy. Rating filters are backed by actual Phase 12 reviews, not fabricated data.
- Chat images await authenticated storage/upload and secure download access.
- Installation-wide, end-to-end mobile app testing is not complete.
