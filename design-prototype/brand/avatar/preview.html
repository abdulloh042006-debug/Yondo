Avatars and stories

Brand preview for the customer avatar set and the companion story rings and cards. Ink, paper and carrot only. Spec: docs/stories-avatars-design.md. Sample names and texts are DEMO; button and label copy is English here, the real copy goes through t('key') in uz, ru and en. The avatar API (users.avatar_code) is planned, not built; the story endpoints already exist.

12 patterns, 3 grounds

Geometric ornament only: no faces, no figures. Each customer gets one of 36 base looks (69 distinct with the fold, see below). Carrot is a graphic fill, never text.

Size ladder

64, 44 and 32 px (96 is the sheet above). Under 44 px the fine layer is dropped so the shapes stay at least 2 px wide.

Fold (phase)

Fold 1 turns the motif by half of its own symmetry step (the single almond is mirrored instead; the pomegranate has no fold), so two accounts with the same pattern and ground still differ. Left of each pair is fold 0.

Derived from an id

Type any id. The same id always gives the same avatar: FNV-1a, then pattern = h mod 12, ground = floor(h/12) mod 3, fold = floor(h/36) mod 2.

Story rings

Built from StoryRing: one arc per active card (count, at most 5 because the server keeps at most 5 active cards). Unseen = 3 px carrot arcs; seen = 1.5 px ink at 60 % (seen state is stored on the device only, the server records no viewers). The photo stand-ins below are ornaments: real rings hold the companion photo, and fall back to the ornament seeded by profile_id when photo is null.

Story cards

Viewer (9:16) for the two kinds: availability and note, then the companion's own list (OwnStory). The photo stand-in sits under a 78 % ink scrim so paper text stays above 8:1 even over a white photo.
